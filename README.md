# Лабораторная работа 4 - вариант 1

Мини-мир: плоские многоугольники. Проект использует C++20, CMake и Google Test.

## Контракт классов

```text
Polygon (абстрактный базовый класс)
├── Triangle
├── Square
└── Pentagon
```

`Polygon` владеет вершинами, задаёт виртуальный интерфейс метрики, проверки корректности, чтения и записи. У базового класса виртуальный деструктор, поэтому фигуры безопасно удаляются через `Polygon*`. `metric()`, `center()`, `isValid()` и методы характеристик не меняют объект и объявлены `const`. Метрика и центр вычисляются по вершинам; центр — среднее арифметическое координат.

| Класс | Допустимые вершины | Метрика | Специфичный метод |
| --- | ---: | --- | --- |
| `Triangle` | 3 | Площадь по формуле шнурка | `isEquilateral()` |
| `Square` | 4 | Площадь по формуле шнурка | `side()` |
| `Pentagon` | 5 | Площадь по формуле шнурка | `isRegular()` |

Фабрика `Polygon::fromVertices<T>()` проверяет число вершин, самопересечения и геометрические инварианты типа. Площадь считается по модулю, поэтому направление обхода вершин не влияет на результат. Сравнение `operator==` сравнивает площади с точностью `EPS`; преобразование в `double` возвращает площадь.

## Коллекция и владение

`PolygonCollection` хранит `std::unique_ptr<Polygon>` внутри `small_vec`. Коллекция владеет добавленными фигурами, не копируется и перемещается. `add()` принимает указатель-владельца, `emplace()` создаёт объект на месте, `erase()` и `clear()` удаляют объекты. Виртуальный деструктор обеспечивает правильное удаление конкретного производного типа. `totalMetric()` возвращает сумму метрик.

`small_vec<T, N>` хранит первые `N` элементов во встроенном буфере, а при превышении ёмкости переходит на динамическую память. Он реализует копирование, перемещение, доступ, итераторы, изменение размера и обмен.

## Формат потоков

`operator<<` и `operator>>` используют один сериализуемый формат: координаты вершин как пары `x y`, разделённые пробелами. Например, треугольник читается и выводится как:

```text
0 0 4 0 2 3
```

Число пар определяется типом уже созданного объекта: три для треугольника, четыре для квадрата, пять для пятиугольника. Имя фигуры, площадь и центр в сериализуемый поток не включаются; их можно получить через методы объекта.

## Сборка и тесты

Google Test загружается CMake через FetchContent при первой настройке, поэтому для этого шага нужен доступ к GitHub.

```bash
cmake -S . -B build
cmake --build build
ctest --test-dir build --output-on-failure
```

Тесты геометрии и коллекции собираются в `oop_lab_4_tests`, тесты контейнера — в `small_vec_tests`.

Для проверки AddressSanitizer, UndefinedBehaviorSanitizer и обнаружения утечек на поддерживаемых GCC/Clang платформах:

```bash
cmake -S . -B build-asan -DENABLE_SANITIZERS=ON
cmake --build build-asan
ASAN_OPTIONS=detect_leaks=1 ctest --test-dir build-asan --output-on-failure
```
